# Conduit V0.3-A 设计：计算字段

- 日期：2026-10-19
- 状态：待确认
- 前置：V0.2-A 物模型与编解码、V0.2-B 历史查询与曲线、V0.2-R 可靠性加固已完成
- 范围：V0.3 的第一阶段，只实现无状态计算字段；告警在后续 V0.3-B 单独设计

## 1. 目标

产品可以在物模型中定义由其他数值属性计算得到的新属性。例如：

```text
Ptotal = Pa + Pb + Pc
Uavg = (Ua + Ub + Uc) / 3
Uunbalance = (max(Ua, Ub, Uc) - min(Ua, Ub, Uc)) / Uavg * 100
```

设备仍只上报原始测点。服务端在物模型校验之后计算派生值，将原始值和计算值放在同一个时间点写入 InfluxDB，并一起更新 Redis 最新值。因此，现有设备详情、历史曲线和后续告警都能像使用普通属性一样使用计算字段。

## 2. 本期范围

本期实现同一条上报内的无状态数值计算：

- 四则运算 `+ - * /`、一元正负号和括号。
- 数字常量，支持小数和科学计数法。
- 引用同一产品的 `DOUBLE`、`INT` 原始属性。
- 引用同一产品中排在依赖之后的其他计算字段。
- 函数 `abs(x)`、`min(x, ...)`、`max(x, ...)`。
- 保存时检查语法、未知引用、非数值引用和循环依赖。
- 计算结果参与范围校验，并写入最新值和历史数据。

本期不实现：

- `delta`、`rate`、滑动平均、累计量差值、每小时用电量等跨消息状态计算。
- 条件表达式、字符串、布尔和枚举计算。
- 用户自定义函数、JavaScript、SpEL、脚本引擎或数据库表达式。
- 跨设备、跨产品或跨租户聚合。
- 历史数据回算；新增或修改计算字段只影响之后收到的数据。
- 单独的计算任务调度。没有新上报时不会产生计算点。

跨消息计算需要明确乱序、重复投递、设备重启、计量表回卷和状态保存语义，作为 V0.3-A2 单独设计。

## 3. 数据模型

Flyway 新增 `V4__computed_properties.sql`，给 `product_property` 增加：

```sql
expression varchar(512)
```

语义：

- `expression is null`：设备上报的普通属性。
- `expression is not null`：服务端计算字段，数据类型必须是 `DOUBLE`。
- 空白表达式在接口层规范化为 `null`，数据库不保存空串。
- 数据库增加约束：`expression is null or data_type = 'DOUBLE'`。

不新建第二张表。计算字段仍是产品属性，因此名称、单位、小数位、范围、说明、导入导出、最新值元数据和历史曲线都沿用现有能力。

### 3.1 修改规则

- 计算字段只能是 `DOUBLE`，创建时选择“计算字段”后类型固定为浮点数。
- `DOUBLE` 普通属性可以增加表达式变成计算字段；计算字段也可以清空表达式变回普通属性。已有历史列类型不变。
- 计算字段可以修改表达式、范围、单位、小数位和说明。
- 属性标识和数据类型继续不可修改。
- 删除或改变被其他计算字段引用的属性时返回 409，并列出引用它的计算字段。
- `replace` 导入以导入后的最终物模型为准统一检查依赖，允许文件内前向引用，不依赖属性排列顺序。

## 4. 表达式语言

### 4.1 语法

```text
expression  := additive
additive    := multiplicative (("+" | "-") multiplicative)*
multiplicative := unary (("*" | "/") unary)*
unary       := ("+" | "-") unary | primary
primary     := NUMBER | IDENTIFIER | function | "(" expression ")"
function    := ("abs" | "min" | "max") "(" arguments ")"
arguments   := expression ("," expression)*
```

- 标识规则与物模型属性一致：`[A-Za-z][A-Za-z0-9_]{0,63}`。
- 函数名小写且为保留字，不能作为属性标识。
- `abs` 只接受 1 个参数；`min`、`max` 至少接受 2 个参数。
- 表达式最长 512 个字符；解析嵌套最多 32 层；单个表达式最多 64 个语法节点。
- 所有运算使用 Java `double`，结果必须有限。

### 4.2 安全边界

实现自有 tokenizer、递归下降解析器和不可变 AST，不调用任何通用脚本引擎，不允许属性访问、方法调用、赋值、反射或 I/O。保存物模型时完成解析和依赖提取，流水线从缓存中取得已经编译的表达式，不在每条消息上重新解析。

### 4.3 计算语义

- `/ 0`、溢出、`NaN` 或无穷大视为本次计算失败。
- 某个依赖没有出现在本条上报及其已成功计算的字段中时，该计算字段本次跳过。
- 一个计算字段失败或缺少依赖，只影响它自身和依赖它的下游计算字段；原始字段仍正常入库。
- 计算结果再按该字段的 `minValue`、`maxValue` 检查。超出范围时本次跳过。
- 设备上报计算字段标识时，该上报值按 `READ_ONLY` 剔除；服务端只采用自己计算的结果。
- 计算按依赖图的拓扑顺序执行，不以数据库行顺序或导入文件顺序决定。

缺少依赖在设备采用分批上报时是正常情况，不写死信。计算失败和越界同样不把原消息送入死信，避免配置错误阻断原始遥测；通过指标和限频日志暴露：

```text
conduit.pipeline.computed_fields{result="success|missing_dependency|evaluation_error|out_of_range|read_only"}
```

`evaluation_error` 首次记 WARN，重复错误限频；其余只记 DEBUG。日志包含产品、设备、计算字段和错误类型，不打印完整遥测值。

## 5. 物模型快照与流水线

`PropertySpec` 增加原始表达式；缓存加载时构建：

- 普通属性映射，用于校验设备上报。
- 按拓扑顺序排列的 `ComputedProperty` 列表，包含编译 AST 和依赖集合。

若数据库中存在无法编译的旧数据，缓存加载失败并视为不可恢复配置错误；正常写接口和 Flyway 约束应阻止这种状态出现。

属性消息处理顺序调整为：

1. 设备身份与产品检查。
2. 按 codec 解码。
3. 校验普通上报字段；设备上报的计算字段记为只读剔除。
4. 按拓扑顺序计算派生字段。
5. 原始合格字段与成功计算字段合并为一个 `TelemetryPoint`。
6. 写 InfluxDB、更新最新值、记录上报字段的剔除明细并 ACK。

只要原始合格字段或成功计算字段至少有一个，就继续写入。两者都为空时沿用 `FIELD_REJECTED`。

## 6. API 与导入导出

现有属性请求和响应增加：

```json
{
  "expression": "Ua * Ia + Ub * Ib + Uc * Ic"
}
```

- `POST /products/{pk}/properties`：创建计算字段时完成整份物模型依赖校验。
- `PUT /products/{pk}/properties/{identifier}`：修改表达式时重新校验整份依赖图。
- `DELETE`：仍被其他计算字段引用时返回 409。
- `GET`、物模型导出：返回表达式；普通属性为 `null`。
- `PUT .../thing-model`：在单项字段规则后，对导入完成后的最终模型做一次依赖图校验；错误项返回对应计算字段标识。

错误示例：

- `表达式语法错误：第 8 个字符缺少右括号`
- `表达式引用了不存在的属性：Ib`
- `表达式只能引用数值属性：status`
- `计算字段存在循环依赖：P1 → P2 → P1`
- `属性 Ua 正被计算字段 Ptotal 引用，不能删除`

## 7. 前端

属性新增/编辑弹窗增加：

- “计算字段”开关。开启后数据类型固定为“浮点数”。
- 表达式多行输入框，最大 512 字符。
- 输入框下显示语法提示：支持属性标识、`+ - * /`、括号和 `abs/min/max`。
- 编辑计算字段时可以修改表达式；编辑普通 `DOUBLE` 属性时可以开启计算字段。
- 服务端返回的语法、引用或循环错误直接展示在弹窗中。

物模型表格增加“来源”列：

- 普通属性显示“设备上报”。
- 计算字段显示“服务端计算”，鼠标悬停或展开时显示表达式。

设备最新值和历史曲线无需新增接口或组件；计算字段沿用现有属性元数据与数值格式化。

## 8. 兼容与迁移

- 新列可空，所有已有属性升级后仍是普通属性，行为不变。
- 现有物模型 JSON 不含 `expression` 时按普通属性导入。
- 计算字段与已有 InfluxDB 列同名时，由于只能使用 `DOUBLE`，仍需遵守现有字段类型不可变化规则。
- 旧客户端忽略响应中的新增字段即可继续工作。
- 回滚应用前应先删除计算字段或清空表达式；旧应用不会计算它们，却可能把同名设备上报当成普通属性。

## 9. 测试

### 9.1 后端单元测试

- 运算优先级、一元运算、括号、科学计数法。
- `abs/min/max` 参数数量和嵌套。
- 非法字符、未知函数、尾随内容、长度/深度/节点限制。
- 依赖提取、前向引用、稳定拓扑排序、直接和间接循环。
- 缺依赖、除零、溢出、范围越界及下游依赖跳过。
- 普通属性上报行为保持不变，设备提供计算字段时按只读剔除。
- 属性规则、删除引用保护、merge/replace 导入后的整图校验。

### 9.2 集成测试

- Flyway 从 V3 升级后旧属性表达式为空。
- 属性 CRUD 和导入导出包含表达式。
- 两级计算字段写入 InfluxDB，并出现在 Redis 最新值。
- 部分依赖缺失时原始字段仍入库，计算字段不产生值。
- 修改表达式后缓存立即失效，新上报使用新公式。
- 租户不能引用或读取其他租户的属性。

### 9.3 前端测试

- 计算字段开关固定类型并显示表达式输入框。
- 普通属性和计算字段表单可以正确回填并生成请求。
- 表格正确显示来源和表达式。
- 保存失败时保留用户输入并显示服务端错误。

## 10. 完成标准

1. 在演示三相电表中新增 `Ptotal = Ua * Ia + Ub * Ib + Uc * Ic`，下一条完整上报后最新值出现总功率。
2. 历史页可以选择 `Ptotal` 并显示曲线，单位和小数位按物模型配置展示。
3. 创建未知引用或循环依赖时无法保存，并得到指向具体字段的错误。
4. 设备只上报部分依赖时，原始值正常入库，计算字段本次不产生值。
5. 设备伪造 `Ptotal` 上报值时不会覆盖服务端计算结果。
6. 后端与前端相关测试通过，现有 V0.2 行为不回归。

## 11. 后续 V0.3-A2 与 V0.3-B

V0.3-A2 再设计跨消息计算，至少需要确定：按设备保存上一有效点、重复消息幂等、乱序策略、累计量回卷、状态过期和历史回算。完成这些语义后才能实现 `delta(EPimp)`、每小时用电量和变化率。

V0.3-B 告警在计算字段稳定后实施，规则可以引用普通属性或计算字段，覆盖阈值、持续时间、离线、产生、恢复、确认、清除以及通知。
