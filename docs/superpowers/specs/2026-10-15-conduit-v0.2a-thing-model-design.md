# Conduit V0.2-A 设计：物模型与编解码

- 日期：2026-10-15
- 状态：已实现（实施计划 docs/superpowers/plans/2026-10-15-conduit-v0.2a-thing-model.md）
- 范围：V0.2 拆分为三个子项目，按顺序实施：**A 物模型与编解码（本文）**、B 历史查询与曲线、C 多租户与用户管理。B、C 另写 spec。
- 前置：V0.1 已完成（`2026-10-14-conduit-v0.1-design.md`）。

## 1. 目标与范围

为每个产品定义物模型（属性），上报数据按物模型逐测点校验；解码改为可插拔，按产品选择解码器。

**本次只做属性**。事件随 V0.3 告警一起设计，服务随 V1.2 下行命令一起设计。

不做：属性读写权限、结构体与数组类型、测点分组、物模型版本与发布流程、脚本解码器（接口预留）。

## 2. 数据模型

### 2.1 `product_property`（Flyway `V2`）

| 字段 | 类型与约束 | 说明 |
|---|---|---|
| `id` | bigserial 主键 | |
| `tenant_id` | bigint 非空，外键 `tenant` | 走租户拦截器 |
| `product_id` | bigint 非空，外键 `product`，`on delete cascade` | |
| `identifier` | varchar(64) 非空 | 正则 `^[A-Za-z][A-Za-z0-9_]{0,63}$`；同一产品内唯一（唯一约束 `(product_id, identifier)`） |
| `name` | varchar(64) 非空 | 显示名称 |
| `data_type` | varchar(16) 非空，CHECK 取值 `DOUBLE`/`INT`/`BOOL`/`TEXT`/`ENUM` | |
| `unit` | varchar(16) | 可空 |
| `min_value` / `max_value` | double precision | 可空；仅 `DOUBLE`、`INT` 生效；同时存在时 `min ≤ max` |
| `decimals` | smallint，CHECK 0～6 | 可空；仅影响显示 |
| `enum_items` | jsonb | `ENUM` 必填，其他类型必须为空；格式 `[{"value":0,"label":"停止"}]`，value 为整数且互不重复，label 非空，最多 64 项 |
| `description` | varchar(256) | 可空 |
| `created_at` / `updated_at` | timestamptz | |

每个产品最多 200 个属性。

### 2.2 `product.codec`

新增列 `codec varchar(32) not null default 'standard-json'`。已有产品升级后使用标准 JSON，行为不变。

### 2.3 类型与 InfluxDB 3 存储类型

| 物模型类型 | InfluxDB 3 字段类型 | Java 值类型 |
|---|---|---|
| `DOUBLE` | float | `Double` |
| `INT` | integer | `Long` |
| `BOOL` | boolean | `Boolean` |
| `TEXT` | string | `String` |
| `ENUM` | integer（存枚举值） | `Long` |

注意：V0.1 把所有数值写成 float。给已有历史数据的测点定义为 `INT`/`ENUM` 会与历史数据类型冲突，新数据进死信 `FIELD_TYPE_CONFLICT`。界面在选择 `INT`/`ENUM` 时提示「已有数据的测点请选择浮点数」。

### 2.4 修改规则

- 名称、单位、范围、小数位数、枚举项、说明可随时修改；属性可随时新增、删除；修改立即生效（见 4.4 缓存）。
- `data_type` 不可修改；要换类型只能删除后用新标识重建。
- 删除属性不删除历史数据，之后上报该测点会被剔除。
- 不做版本管理。

## 3. 解码器

### 3.1 接口（`dev.conduit.server.pipeline.codec`）

```java
public interface PayloadDecoder {
    String name();          // 产品 codec 列存的值
    String displayName();   // 下拉框显示名
    DecodedPayload decode(DecodeContext ctx, byte[] payload);
}

public record DecodeContext(String productKey, String deviceKey, long receivedAt) {}
public record DecodedPayload(long ts, Map<String, Object> values) {}
```

- 解码器只负责格式翻译，**返回原始类型**：整数为 `Long`（超出 long 范围为 `BigInteger`）、小数为 `Double`、文本 `String`、布尔 `Boolean`，不做按类型转换。
- 失败抛 `DecodeException`，原因码沿用 `MALFORMED_JSON`、`INVALID_PARAMS`、`TS_OUT_OF_RANGE`。
- 测点名不能为空、不能以 `__` 开头（保留），违反时 `INVALID_PARAMS`。
- 时间戳规则抽为 `TimestampPolicy`：毫秒整数，范围 `[now − 30 天, now + 5 分钟]`，缺省取接收时间。所有解码器共用。
- 继续拒绝重复键与尾随字符（`MALFORMED_JSON`）。
- `DecodeContext` 为将来的脚本解码器预留：脚本解码器凭 `productKey` 找到产品脚本，接口不变。

### 3.2 内置解码器

| `name` | `displayName` | 格式 |
|---|---|---|
| `standard-json` | 标准 JSON | `{"id":"…","ts":1760400000000,"params":{"Ua":220.1}}`（V0.1 格式） |
| `flat-json` | 扁平 JSON | `{"ts":1760400000000,"Ua":220.1,"Ia":5.2}`：顶层 `ts` 为时间戳，`id` 忽略，其余键均为测点；除 `ts`、`id` 外至少一个测点，否则 `INVALID_PARAMS` |

### 3.3 注册与路由

- `DecoderRegistry` 收集所有 `PayloadDecoder` Bean，按 `name` 索引；重名时启动失败。
- 流水线按产品的 `codec` 找解码器；找不到时整条消息进死信，原因码新增 `UNKNOWN_CODEC`。
- 产品保存时校验 `codec` 存在，不存在返回 400。
- 新增格式：写一个 `@Component` 实现，重新部署；不改流水线、不改数据库。

## 4. 流水线中的校验

### 4.1 属性消息处理顺序

1. 设备身份检查（沿用）：`UNKNOWN_DEVICE`、`DEVICE_DISABLED`、`PRODUCT_MISMATCH`。
2. 从物模型缓存取产品配置 `ProductProfile(codec, properties)`。
3. 查解码器，找不到 → `UNKNOWN_CODEC`。
4. 解码，失败 → 对应原因码。
5. 逐测点校验（4.2）。
6. 合格测点写 InfluxDB、更新最新值、确认消息（沿用）；被剔除的测点另写一条死信记录（4.3）。

### 4.2 校验规则

产品**没有物模型**时，与 V0.1 一致：数值转 `Double`，文本、布尔原样，非有限数值 → 整条 `INVALID_PARAMS`。

有物模型时逐测点判断：

| 情况 | 结果（剔除原因） |
|---|---|
| 物模型中未定义 | 剔除 `UNDEFINED` |
| `DOUBLE`：有限数值 → `Double`；其他 | 剔除 `TYPE_MISMATCH` |
| `INT`：整数且在 long 范围内 → `Long`；小数、超范围整数、非数值 | 剔除 `TYPE_MISMATCH` |
| `BOOL`：布尔；其他 | 剔除 `TYPE_MISMATCH` |
| `TEXT`：字符串且长度 ≤ 1024；超长 | 剔除 `TOO_LONG`；非字符串 `TYPE_MISMATCH` |
| `ENUM`：整数且为定义的枚举值；整数但不在枚举中 | 剔除 `ENUM_VALUE`；非整数 `TYPE_MISMATCH` |
| `DOUBLE`/`INT` 超出 `min_value`～`max_value` | 剔除 `OUT_OF_RANGE` |

整数判断：`Long`、`BigInteger`，或值为整数的 `Double`（如 `220.0`）均视为整数。

### 4.3 剔除的记录

- 全部测点被剔除：整条消息进死信，原因 `FIELD_REJECTED`，不写入数据。
- 部分被剔除：合格测点照常入库并确认消息；另写一条死信记录，原因 `FIELD_REJECTED`，包含原始消息字段，外加字段 `rejected`，值为 JSON 数组 `[{"field":"Ua","value":"abc","reason":"TYPE_MISMATCH"}]`（`value` 原值，过长时截断到 64 字符）。
- `MessageBus` 新增 `void recordDead(Delivery delivery, String reason, Map<String,String> details)`：只写死信流、不确认。现有 `deadLetter(group, delivery, reason)` 改为调用它后再确认。
- 指标：`conduit.pipeline.rejected_fields{reason}` 按剔除原因计数；`conduit.pipeline.dead{reason}` 照旧。

### 4.4 物模型缓存

- `ThingModelCache`：Caffeine，按 `productKey` 缓存 `ProductProfile`，写入后 60 秒过期，最多 10 000 项；跨租户查询（流水线无租户上下文，与设备身份查询相同做法）。
- 产品不存在（缓存未命中且数据库无记录）时，不缓存，由设备身份检查兜底。
- 通过接口修改属性、导入物模型、修改产品 `codec`、删除产品时，主动清除该产品缓存。单实例立即生效，多实例最多延迟 60 秒。
- 读数据库失败为可恢复错误，沿用原地退避重试。

### 4.5 InfluxDB 写入

`TelemetryWriter` 按值类型写字段：`Long` → integer，`Double` → float，`Boolean` → boolean，`String` → string。其余类型视为转换失败（写入前按点剔除；写入时被 InfluxDB 逐行拒绝的点按行号映射回消息）。

## 5. 接口

所有接口在 `/api/v1` 下，租户隔离，错误为 ProblemDetail。

| 接口 | 说明 |
|---|---|
| `GET /codecs` | `[{name, displayName}]` |
| `POST /products`、`PUT /products/{pk}` | 请求体新增可选 `codec`，默认 `standard-json`；不存在返回 400 |
| `GET /products`、`GET /products/{pk}` | 视图新增 `codec`、`propertyCount` |
| `GET /products/{pk}/properties` | 属性列表，按创建顺序 |
| `POST /products/{pk}/properties` | 新增，201；标识重复 409；超过 200 个 409 |
| `PUT /products/{pk}/properties/{identifier}` | 修改；请求中 `dataType` 与现值不同返回 409「数据类型不可修改」 |
| `DELETE /products/{pk}/properties/{identifier}` | 204 |
| `GET /products/{pk}/thing-model` | 导出 `{"properties":[…]}`，每项为 8 个字段 |
| `PUT /products/{pk}/thing-model?mode=merge\|replace` | 导入，见下 |

**导入**：`merge` 新增或更新文件中的属性，保留其他；`replace` 以文件为准，删除文件中没有的属性。先校验整个文件，任一错误（标识非法或重复、类型变更、枚举项不合法、超过 200 个等）则整体不生效，返回 400，ProblemDetail 带 `errors: [{identifier, message}]` 列出全部错误；成功则在一个事务中完成并清除缓存，返回导入后的属性列表。

**属性校验**（新增、修改、导入共用）：标识正则与保留前缀；`min ≤ max`；`decimals` 0～6；`ENUM` 必须有合法枚举项，其他类型不能有；`BOOL`/`TEXT`/`ENUM` 不能设范围。

**最新值** `GET /devices/{dk}/latest`：每个测点新增 `name`、`unit`、`decimals`、`enumLabel`（物模型中无定义或不是枚举时为 null）。

## 6. 前端

- **产品列表**：新增「解码器」「属性数」两列；产品名可点击进入产品详情。
- **产品详情页** `/products/:productKey`，两个标签页：
  - **基本信息**：名称、描述、解码器下拉框（来自 `/codecs`）。
  - **物模型**：属性表格（标识、名称、类型、单位、范围、小数位数、操作）。新增/编辑弹窗按类型显示字段：数值类型显示范围和小数位数，枚举显示枚举项编辑，文本、布尔不显示范围；编辑时类型不可改。选择 `INT`/`ENUM` 时显示 2.3 的提示。表格上方「导入」（选择文件、选择合并或替换、确认，失败时展示错误列表）、「导出」（下载 JSON）。
- **设备详情**：最新值表格显示「名称（标识）」、按小数位数格式化并带单位的值、枚举显示标签。

## 7. 演示与模拟器

- 新增 `docs/examples/demo-meter.thing-model.json`：`Ua/Ub/Uc`（A/B/C 相电压，V）、`Ia/Ib/Ic`（A/B/C 相电流，A）、`EPimp`（正向有功电能，kWh），全部 `DOUBLE`，电压、电流 1 位小数，电能 3 位小数。
- 模拟器开通产品后，若产品属性数为 0，自动导入该示例（文件打包进模拟器 jar 的 classpath）。
- 模拟器新增环境变量 `SIM_PAYLOAD_FORMAT`：`standard`（默认）或 `flat`。

## 8. 迁移与兼容

- Flyway `V2`：建表、加列，不改已有数据。
- 已有产品无物模型 → V0.1 行为，不会拒收。
- 演示环境重新构建后，容器模拟器重启时为「Demo Meter」导入物模型，此后演示数据按物模型校验。
- 死信流新增原因码 `UNKNOWN_CODEC`、`FIELD_REJECTED`，以及 `rejected` 字段；已有记录格式不变。

## 10. 完成标准

1. 「Demo Meter」自动具备物模型，设备详情显示名称与单位，如「A 相电压 220.1 V」。

3. 上报一个未定义测点和一个超范围值：合格测点入库，两个被剔除测点在死信中可查，原因分别为 `UNDEFINED`、`OUT_OF_RANGE`。
