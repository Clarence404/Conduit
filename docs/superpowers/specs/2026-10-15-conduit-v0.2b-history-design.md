# Conduit V0.2-B 设计：历史查询与曲线

- 日期：2026-10-15
- 状态：已评审，待实现
- 范围：V0.2 的第二个子项目（A 物模型与编解码已完成，C 多租户与用户管理另写 spec）。
- 前置：V0.2-A（`2026-10-15-conduit-v0.2a-thing-model-design.md`），时序库 InfluxDB 3 Core 3.12.0，表 `property`，每个测点一列，类型按物模型。

## 1. 目标与范围

在设备详情页查看单台设备一个或多个测点的历史曲线。时间范围大时由服务端自动聚合，前端只选时间范围。

本次包含：

- 历史接口 `GET /api/v1/devices/{deviceKey}/history`（原始 / 自动聚合两种模式）。
- 设备详情页「历史」标签页：快捷时间范围与自定义起止、测点多选、每测点一张联动小图、框选缩放后重新查询、最近时段自动刷新。
- 顺带修复：模拟器启动时连不上 EMQX 即退出的问题（见第 6 节）。

不包含：多设备对比、总览首页、CSV 导出、文本测点历史表格、降采样与持续查询（V1.0）。

## 2. 接口

```
GET /api/v1/devices/{deviceKey}/history?properties=Ua,Ia,st&from=<毫秒>&to=<毫秒>
```

### 2.1 参数与校验

| 参数 | 规则 |
|---|---|
| `deviceKey` | 按当前租户查设备，不存在或属于其他租户 → 404 |
| `properties` | 逗号分隔，1～8 个，去重；每个须匹配 `^[A-Za-z][A-Za-z0-9_]{0,63}$`，否则 400 |
| `from` / `to` | 毫秒时间戳；都不传时为最近 1 小时（`to` = 当前时间）；只传一个 → 400；须 `from < to`，跨度 1 分钟～30 天，否则 400 |

测点类型的确定：物模型中有定义的按物模型类型；物模型没有的，按 InfluxDB 实际列类型——浮点/整数视为数值，布尔视为状态，字符串 → 400「文本测点不支持历史曲线」。列不存在（从未上报）的测点返回空曲线，不报错。物模型中定义为 `TEXT` 的测点 → 400。

### 2.2 原始与聚合

1. 先用一条 SQL 统计每个测点在 `[from, to)` 内的非空点数。
2. 所有测点的点数都 ≤ **1000**：原始模式，返回原始点（按时间升序）。
3. 否则聚合模式：时间桶取下列档位中能使 `(to − from) / 桶 ≤ 1000` 的最小档：1 秒、5 秒、10 秒、30 秒、1 分钟、5 分钟、15 分钟、30 分钟、1 小时、3 小时、6 小时、12 小时。用 `date_bin(INTERVAL '<n> seconds', time)` 分组（原点 1970-01-01，相邻请求的桶边界一致）。
   - 数值测点（`DOUBLE`、`INT`、无物模型的数值列）：每桶 `avg`、`min`、`max`，`mode = AGG`。
   - 状态测点（`BOOL`、`ENUM`）：每桶最后一个值（InfluxDB 3 的 `selector_last(col, time)['value']`），`mode = LAST`。
   - 某测点在某桶内没有值时，该桶不输出该测点的点。
   - 最后一个桶可能不完整，照常返回。

原始模式下各测点 `mode = RAW`。同一次请求所有测点使用同一模式和同一时间桶。

### 2.3 返回

```json
{
  "deviceKey": "…", "from": 1760400000000, "to": 1760486400000,
  "bucketMs": 60000,
  "series": [
    { "identifier": "Ua", "name": "A 相电压", "dataType": "DOUBLE", "unit": "V", "decimals": 1,
      "enumItems": null, "mode": "AGG", "points": [[1760400000000, 220.1, 219.8, 220.5]] },
    { "identifier": "st", "name": "状态", "dataType": "ENUM", "unit": null, "decimals": null,
      "enumItems": [{"value": 0, "label": "停机"}, {"value": 1, "label": "运行"}],
      "mode": "LAST", "points": [[1760400000000, 1]] }
  ]
}
```

- `bucketMs`：原始模式为 `null`。
- `points`：`RAW`/`LAST` 为 `[ts, value]`，`AGG` 为 `[ts, avg, min, max]`；`ts` 为毫秒（聚合模式为桶起点）。布尔值以 `true`/`false` 返回。
- `series` 顺序与请求中 `properties` 的顺序一致。
- 无物模型的测点：`name`、`unit`、`decimals`、`enumItems` 为 `null`，`dataType` 按列类型取 `DOUBLE`/`INT`/`BOOL`。

### 2.4 错误

| 情况 | 响应 |
|---|---|
| 参数不合法、文本测点 | 400，ProblemDetail，`detail` 说明原因 |
| 设备不存在或其他租户 | 404 |
| InfluxDB 不可达或返回 5xx | 503「时序库暂不可用」 |
| 其他查询错误 | 500，不暴露 SQL |

## 3. 后端实现

代码放在 `conduit-server` 的 `telemetry` 包：

| 单元 | 职责 |
|---|---|
| `HistoryController` | 参数解析与校验，按租户查设备（`DeviceService`），取物模型（`ThingModelCache`），调用 service |
| `HistoryService` | 确定测点类型，计数，选模式与时间桶，执行查询，组装 `series` |
| `BucketPolicy` | 纯函数：按跨度与上限 1000 选时间桶档位 |
| `HistoryQueryBuilder` | 纯函数：生成计数、原始、聚合三种 SQL 与参数 |
| `InfluxSchema` | 查询 `information_schema.columns`（`table_name = 'property'`）得到列名与类型，缓存 60 秒；请求中出现未知列时强制刷新一次 |
| `InfluxClient.querySql(sql, params)` | POST `/api/v3/query_sql`，`format=json`，参数化查询 |

- **租户隔离**：SQL 条件固定为 `tenant_id = $tenant AND product_key = $product AND device_key = $device AND time >= $from AND time < $to`，值全部经 `params` 传入。
- **防注入**：列名只使用通过 2.1 正则校验、且确认存在于 `InfluxSchema` 的标识符，统一加双引号；SQL 中不拼接任何请求值。
- **时间**：接口用毫秒；InfluxDB 返回的 `time` 为不带时区的 UTC 字符串，在服务端转换。
- **函数验证**：`selector_last`、参数化查询、`date_bin` 在实现计划第一个任务中先对真实 3.12.0 探测，确认语法与返回格式。
- **性能目标**：单设备、8 个测点、30 天（每 10 秒一点，约 26 万行）接口耗时 < 1 秒，验收时实测记录。

## 4. 前端

- 设备详情页改为两个标签页「最新值 | 历史」，标签与路由 query `tab`（`latest`/`history`）同步，用 `router.replace`。
- 历史页工具栏：
  - 快捷范围：最近 1 小时（默认）、6 小时、24 小时、7 天、30 天；自定义起止（`el-date-picker` datetimerange）。
  - 测点多选（最多 8 个）：候选为物模型中非 `TEXT` 属性，加最新值中出现、物模型未定义的数值或布尔测点；默认选中前 4 个数值测点。
  - 「重置缩放」「刷新」按钮；聚合时显示「已按 N 分钟聚合（平均/最小/最大）」，原始时显示「原始数据」。
- 图表（ECharts，按需引入 `LineChart`、`GridComponent`、`TooltipComponent`、`ToolboxComponent`、`DataZoomComponent`、`MarkAreaComponent`、`CanvasRenderer`；不引入 `vue-echarts`）：
  - 每个测点一张图，上下排列，高约 180px，共用 `echarts.connect` 分组，十字线与提示联动。
  - 数值：平均值折线 + 最小～最大浅色波动带（`AGG`），原始模式仅折线；纵轴名为单位；提示数值按 `decimals` 格式化。
  - 状态：阶梯线（`step: 'end'`），纵轴刻度为「否/是」或枚举标签。
  - 无数据：显示「该时段没有数据」。
- 交互：工具栏区域缩放框选后，以选中范围重新请求（范围不足 1 分钟时按 1 分钟）；缩放后暂停自动刷新，「重置缩放」恢复原范围。
- 自动刷新：快捷范围且未缩放时每 30 秒刷新（复用 `usePolling`，页面隐藏时暂停）；自定义范围不自动刷新。
- 请求乱序保护：使用请求序号，过期响应丢弃。
- 代码：`api/history.ts`、`utils/historyRange.ts`（时间范围与快捷项）、`utils/historyChart.ts`（返回数据 → ECharts option）、`utils/historyProperties.ts`（测点候选与默认选中）、`components/HistoryPanel.vue`。
- 遵守项目界面约定（分页每页 10 条、中文文案）；本页无分页表格。

## 5. 演示

演示产品「三相电表（演示）」的 7 个属性均为 `DOUBLE`。为验收状态曲线，在演示物模型 `docs/examples/demo-meter.thing-model.json` 中新增枚举属性 `st`「运行状态」（0 停机、1 运行、2 检修），模拟器按设备每小时切换一次状态（多数时间为 1）。`ensureThingModel` 只在产品没有属性时导入，因此在已有部署上用 merge 模式补导新属性：模拟器改为「产品缺少演示模型中的任一属性时，以 merge 模式导入」。

## 6. 模拟器连接重试（顺带修复）

现象：重新部署时 EMQX、server 同时重启，EMQX 的鉴权回调 server 尚未就绪，模拟器首次连接超时后整个进程退出，依赖 compose 重启。

修复：设备首次连接失败时重试，间隔 2 秒、最多 15 次（约 30 秒）；全部失败才退出。重试期间每 5 次打印一条 WARN，不打印 ERROR 堆栈。

## 7. 测试

后端：

- 单元：`BucketPolicy` 各档位边界（30 天 → 1 小时）；`HistoryQueryBuilder` 生成的 SQL 与参数、非法标识符拒绝；参数校验（0/9 个测点、`from ≥ to`、跨度超 30 天、只传一个时间、文本测点）。
- 集成（Testcontainers：InfluxDB 3.12.0 + PostgreSQL）：写入已知数据后验证原始模式值；聚合模式 avg/min/max 与桶边界；枚举、布尔取桶内最后值；不存在的列返回空曲线；无物模型测点按列类型；其他租户设备 404；InfluxDB 停止时 503。

前端（Vitest）：`historyRange` 快捷项换算；`historyChart` 生成的 option（波动带、阶梯线与枚举刻度、空数据）；`historyProperties` 候选过滤、上限 8、默认选中；`HistoryPanel` 组件测试：缩放触发重新请求并暂停刷新、重置恢复、乱序响应被丢弃。

模拟器：连接失败若干次后成功则继续；全部失败则抛出。

## 8. 完成标准

在演示环境上：

1. 「三相电表（演示）」任一设备的「历史」页，最近 1 小时显示 4 张图，原始模式，最新点与「最新值」一致。
2. 切到 24 小时显示「已按 1 分钟聚合」，曲线连续且有波动带。
3. 运行状态 `st` 显示为阶梯线，纵轴为「停机/运行/检修」。
4. 在 24 小时图上框选约 10 分钟，重新查询后为原始点，所有图同步缩放，「重置缩放」回到 24 小时。
5. 用另一个租户的令牌请求该设备历史接口返回 404。
6. 30 天范围接口耗时记录在验收结果中（目标 < 1 秒）。
7. 重新部署（`deploy/build-local.sh`）后模拟器日志中没有 `Simulator failed`。
