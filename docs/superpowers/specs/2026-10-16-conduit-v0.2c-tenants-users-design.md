# Conduit V0.2-C 设计：多租户与用户管理

- 日期：2026-10-16
- 状态：已评审，待实现
- 范围：V0.2 的第三个子项目（A 物模型与编解码、B 历史查询与曲线已完成）。
- 前置：V0.1 起所有业务表带 `tenant_id`，MyBatis-Plus 租户拦截器按 JWT 中的租户过滤；已有表 `tenant`（code / name / status）与 `app_user`（tenant_id / username 全局唯一 / password_hash / role / status）；只有启动时创建的默认租户 `default` 与管理员 `admin`。界面刷新已在侧栏「系统管理」预留「用户」「租户」两个禁用项。

## 1. 目标与范围

把单租户的 V0.1 变成可用的多租户平台：平台管理员管理租户、可进入任一租户代为操作；租户管理员管理本租户的产品、设备与用户；只读用户只能查看。满足路线图 V0.2 的验收：两租户两型号数据互不可见。

不包含：邮件找回密码、多因素认证、登录失败锁定、操作审计表（V1.0）、租户配额、停用时主动踢下线 MQTT 会话（见 backlog）。

## 2. 角色与数据模型

### 2.1 角色

| 角色 | 值 | 所属 | 能力 |
|---|---|---|---|
| 平台管理员 | `PLATFORM_ADMIN` | 不属于任何租户 | 租户管理、平台概况、查看租户用户、重置租户管理员密码、进入租户（进入后等同租户管理员） |
| 租户管理员 | `TENANT_ADMIN` | 一个租户 | 本租户全部读写，含用户管理 |
| 只读用户 | `TENANT_VIEWER` | 一个租户 | 本租户只读 |

### 2.2 迁移 V3

- `app_user`：
  - `tenant_id` 改为可空；约束 `(role = 'PLATFORM_ADMIN') = (tenant_id is null)`。
  - 角色约束：`role in ('PLATFORM_ADMIN','TENANT_ADMIN','TENANT_VIEWER')`；现有 `ADMIN` 迁移为 `TENANT_ADMIN`。
  - 新增 `display_name varchar(64)`（为空时界面显示用户名）、`must_change_password boolean not null default false`、`updated_at timestamptz not null default now()`。
  - `status` 沿用：`ACTIVE` 启用 / `DISABLED` 禁用（加约束）。
- `tenant`：
  - `status` 沿用：`ACTIVE` / `DISABLED`（加约束）；新增 `updated_at`。
  - 编码规则 `^[a-z][a-z0-9-]{1,31}$`（2～32 位），全局唯一，创建后不可修改；默认租户编码 `default` 不变。
- 删除租户时其用户随之删除（用户外键改为 `on delete cascade`，或由服务在同一事务中先删用户）。

### 2.3 初始化

- 保留现有逻辑：没有默认租户与 `admin` 时创建（`admin` 现为默认租户的 `TENANT_ADMIN`）。
- 新增：没有任何平台管理员时，用 `CONDUIT_PLATFORM_ADMIN_USERNAME`（默认 `sysadmin`）与 `CONDUIT_PLATFORM_ADMIN_PASSWORD` 创建；密码为空则不创建，打一条 WARN，不阻止启动。

### 2.4 规则

- 用户名：3～32 位，字母开头，只能含字母、数字、`_`、`-`、`.`；全平台唯一，重复 409。登录不需要选择租户。
- 密码：至少 8 位，同时含字母和数字；BCrypt。
- 平台接口没有租户上下文，跨租户查询必须显式标注（与按 productKey 跨租户查产品相同的做法）。

## 3. 认证、令牌与权限

### 3.1 令牌

沿用 JWT（access 15 分钟、refresh 7 天、refresh 存 HttpOnly Cookie）。声明：用户 id、`tid`（平台管理员为空）、`role`（有效角色）、`typ`；进入租户时增加 `imp`（代入的平台管理员用户 id），此时 `tid` 为目标租户、有效角色为 `TENANT_ADMIN`。

### 3.2 登录与续期检查

- 登录拒绝：用户 `DISABLED`；所属租户 `DISABLED`。
- 续期时重新读取数据库：用户禁用、租户停用、角色变化在下次续期生效（最长延迟为 access 有效期 15 分钟）；代入令牌续期时若目标租户已停用或删除，退回平台管理员自己的令牌。

### 3.3 权限矩阵（后端统一按路径与方法判断，前端只做隐藏）

| 接口 | 允许 |
|---|---|
| `/api/v1/platform/**` | 未代入的平台管理员 |
| 租户内接口 GET | 租户管理员、只读用户、代入的平台管理员 |
| 租户内接口 POST / PUT / DELETE | 租户管理员、代入的平台管理员 |
| `/api/v1/users/**` | 租户管理员、代入的平台管理员 |
| `/api/v1/me/**`、`/api/v1/auth/**` | 所有登录用户（auth 中登录、续期、登出照旧公开） |

未代入的平台管理员访问租户内接口返回 403；租户用户访问平台接口返回 403。

### 3.4 强制修改密码

用户 `must_change_password = true` 时登录照常成功，但除 `PUT /api/v1/me/password`、`GET /api/v1/auth/me`、登出外，所有接口返回 403，ProblemDetail 属性 `code = PASSWORD_CHANGE_REQUIRED`。

### 3.5 进入与退出租户

- `POST /api/v1/platform/tenants/{code}/enter`：签发代入令牌（access + refresh），记 INFO 日志（平台管理员、租户）。停用的租户不能进入（409）。
- `POST /api/v1/auth/exit-tenant`：换回平台管理员自己的令牌，记 INFO 日志。
- 代入期间每个写请求（POST/PUT/DELETE）记一行 INFO：平台管理员用户名、租户编码、方法、路径（不记请求体）。V1.0 并入审计表。

### 3.6 停用租户对设备的影响

- MQTT 鉴权检查租户状态：停用租户的设备连接被拒；停用时清除该租户设备的鉴权缓存（`conduit:auth:*`）。
- 已连接的设备后续上报进入新增死信原因 `TENANT_DISABLED`（流水线身份查询带租户状态，与 `DEVICE_DISABLED` 处理一致）。
- 默认租户不能停用、不能删除（409）。

## 4. 接口

前缀 `/api/v1`，错误为 ProblemDetail：400 参数、403 权限、404 不存在、409 冲突。

### 4.1 平台（未代入的平台管理员）

| 方法与路径 | 说明 |
|---|---|
| `GET /platform/overview` | `{tenantCount, activeTenantCount, disabledTenantCount, userCount, productCount, deviceCount, onlineCount, topTenants:[{code,name,deviceCount,onlineCount}]}`；`topTenants` 为设备数最多的 5 个；Redis 不可用时在线相关为 null |
| `GET /platform/tenants?keyword&status&page&size` | 每页默认 10；`keyword` 匹配名称或编码；项 `{code,name,status,adminCount,userCount,productCount,deviceCount,onlineCount,createdAt}` |
| `POST /platform/tenants` | `{code,name,admin:{username,displayName,password}}`，同一事务；管理员 `must_change_password=true`；201 |
| `PUT /platform/tenants/{code}` | `{name}` |
| `POST /platform/tenants/{code}/disable`、`/enable` | 默认租户 409 |
| `DELETE /platform/tenants/{code}` | 有产品或设备、或为默认租户时 409；同时删除其用户；204 |
| `GET /platform/tenants/{code}/users` | 该租户用户列表（不分页，按角色、用户名排序） |
| `POST /platform/tenants/{code}/users/{username}/reset-password` | `{password}`；仅限 `TENANT_ADMIN`，否则 409；置 `must_change_password=true` |
| `POST /platform/tenants/{code}/enter` | 见 3.5 |

### 4.2 租户用户管理（租户管理员、代入的平台管理员）

| 方法与路径 | 说明 |
|---|---|
| `GET /users?keyword&role&status&page&size` | 每页默认 10；项 `{username,displayName,role,status,mustChangePassword,createdAt}` |
| `POST /users` | `{username,displayName,role,password}`，`role` 只能是 `TENANT_ADMIN` / `TENANT_VIEWER`；`must_change_password=true`；201 |
| `PUT /users/{username}` | `{displayName,role}` |
| `POST /users/{username}/disable`、`/enable` | |
| `POST /users/{username}/reset-password` | `{password}`；置 `must_change_password=true` |
| `DELETE /users/{username}` | 204 |

保护规则（409）：不能删除、禁用自己或修改自己的角色；本租户最后一个启用的 `TENANT_ADMIN` 不能被降级、禁用或删除。代入的平台管理员不算本租户用户，不受「自己」规则约束，但受「最后一个管理员」规则约束。

### 4.3 个人

- `GET /auth/me`：`{username,displayName,role,tenantCode,tenantName,mustChangePassword,impersonatedBy}`（`impersonatedBy` 为代入的平台管理员用户名，未代入为 null）。
- `PUT /me`：`{displayName}`。
- `PUT /me/password`：`{oldPassword,newPassword}`；成功后清除 `must_change_password`。代入令牌不能调用（409），平台管理员退出后修改自己的密码。

## 5. 前端

### 5.1 菜单与路由

| 身份 | 菜单 |
|---|---|
| 平台管理员（未代入） | 概览（平台首页）；系统管理 → 租户 |
| 租户管理员 / 代入的平台管理员 | 概览；设备接入 → 产品、设备；系统管理 → 用户 |
| 只读用户 | 概览；设备接入 → 产品、设备 |

路由守卫：未代入的平台管理员访问租户页面跳到租户管理，`/home` 显示平台首页；租户用户访问平台页面跳到首页。新页面登记在 `ROUTE_META`。

### 5.2 页面与组件

- 平台首页：4 个指标卡（租户、用户、设备、在线率）与「设备最多的租户」列表（点击进入租户管理并按该租户筛选）。
- 租户管理：`useTable` + `FilterBar`（名称、状态）；操作列「进入、编辑、用户、停用/启用、删除」；「新建租户」对话框分「租户信息」「首个管理员」两块；「用户」为抽屉，列出该租户用户，`TENANT_ADMIN` 行有「重置密码」。
- 用户管理：`useTable` + `FilterBar`（关键字、角色、状态）；新建、编辑、重置密码对话框；角色与状态用 `el-tag`；自己那一行不显示删除、禁用。
- 个人设置：用户菜单进入，对话框含「基本信息」（显示名称）与「修改密码」。
- 强制改密码对话框：`/auth/me` 返回需改密码或任一接口返回 `PASSWORD_CHANGE_REQUIRED` 时弹出，不可关闭。
- 进入租户：确认框「将以租户管理员权限操作租户 XX 的数据，所有修改都会被记录」；进入后顶栏下方固定醒目提示条「正在以平台管理员身份操作租户：XX」与「退出」按钮。
- 顶栏用户菜单显示显示名称（无则用户名）与角色。

### 5.3 权限

`usePermission()` 提供 `isPlatformAdmin`、`isImpersonating`、`canWrite`、`canManageUsers`。所有写操作按钮按 `canWrite` 显示，包括现有的产品、物模型、设备页面（新建、编辑、删除、导入、启用/禁用、重置密钥）。

## 6. 测试

后端：

- 迁移：`admin` 变为 `TENANT_ADMIN`；平台管理员租户为空的约束；角色、状态约束。
- 权限矩阵集成测试：三种角色与代入身份，逐类访问平台接口、租户读、租户写、用户管理、个人接口。
- 租户生命周期：创建（事务性，任一失败不留数据）、改名、停用（登录被拒、续期被拒、MQTT 鉴权被拒、已连接设备上报进入 `TENANT_DISABLED` 死信）、启用、删除（有数据 409、默认租户 409、用户随之删除）。
- 用户：保护规则、用户名与密码规则、重复 409、禁用后续期失败、角色变化在续期后生效。
- 强制改密码：带标记时其余接口 403，修改后恢复。
- 代入：进入后读写目标租户且看不到其他租户；写请求有 INFO 日志；退出恢复平台身份；目标租户停用后续期退回平台身份。
- 初始化：平台管理员按环境变量创建；密码为空只警告。
- 两租户隔离：两个租户各自的产品、设备、历史、首页统计互不可见。

前端：`usePermission`、各身份菜单、路由守卫、只读用户无写按钮、代入提示条与退出、强制改密码对话框、租户管理与用户管理页面、个人设置。

## 7. 验收

对本地运行的整套服务做接口检查，界面项由所有者目视：

1. `sysadmin` 登录，新建「验收租户（华东）」及其管理员；该管理员首次登录被要求改密码。
2. 新租户管理员建一个产品和一台设备；`admin` 看不到，新租户也看不到演示数据。
3. 新租户建只读用户：能查看，写操作 403。
4. `sysadmin` 进入新租户，能读能改，日志有记录；退出回到租户管理。
5. 停用新租户：其用户登录被拒、设备 MQTT 连接被拒；启用后恢复。
6. 删除新租户的设备与产品后删除租户。

验收结束清理所创建的数据。
