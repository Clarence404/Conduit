# Conduit 生产级 IoT SaaS Roadmap

- 日期：2026-10-20
- 状态：当前生效
- 产品目标：建设面向工业、能源、园区与设备运营场景的生产级多租户 IoT SaaS 平台；核心能力对标 ThingsBoard，但不以逐项复制为目标。

## 1. 产品边界

Conduit 的核心价值是可靠设备接入、统一物模型、实时数据处理、设备运营与多租户服务。平台同时支持公有 SaaS、客户独立部署和边缘节点接入，三种形态共享核心领域模型与协议，不维护三套产品。

近期不自建通用低代码平台、消息中间件或支付系统；优先把 IoT 控制面、数据面、租户治理和可运营能力做完整。与 ThingsBoard 的竞争应聚焦于更清晰的产品模型、更可靠的上报语义、更低的部署复杂度和更适合国内工业场景的交付体验。

## 2. 当前基线与关键差距

当前 V0.2 已具备 MQTT 接入、设备鉴权、物模型、多租户基础、最新值与历史曲线、可靠上报、双 Transport 单活多备、演示资产和完整容器部署。

距离生产级 SaaS 仍有六类关键差距：

1. 租户隔离主要依赖应用逻辑，尚无数据库强制隔离、细粒度权限、配额和资源治理。
2. 缺少租户注册、邀请、套餐、用量计量、账单和生命周期管理，尚未形成 SaaS 商业闭环。
3. 缺少 RPC、设备影子、属性同步、网关/子设备、OTA 和完整凭据生命周期。
4. 缺少可配置规则引擎、告警闭环、通知升级、仪表盘与资产关系模型。
5. 部署仍以单机 Compose 为主，缺少水平扩展、滚动升级、备份恢复、灾备演练和容量 SLO。
6. 开放 API、Webhook、数据转发、连接器 SDK、审计与企业身份集成尚不完整。

## 3. 路线原则

- 先安全边界与平台治理，再增加业务功能；任何新数据模型必须先定义租户归属、权限、配额和审计。
- 控制面与数据面逐步解耦；设备接入、消息处理、查询和管理 API 可以独立扩缩容。
- 所有异步处理都要可重放、幂等、可观测；所有外部调用都要有超时、重试、熔断和死信策略。
- SaaS 与独立部署使用同一代码基线，通过能力开关、部署拓扑和许可证/套餐控制差异。
- 演示数据不得进入生产租户。V4 历史迁移保持不可变，但在首次正式生产发布前建立无演示种子的生产基线；开发和演示数据改由显式 profile 或初始化任务创建。
- 每阶段必须同时交付功能、迁移/回滚方案、容量指标、监控、审计、安全测试和运维文档。

## 4. 分阶段 Roadmap

### V0.3：SaaS 基座与安全边界

- 租户上下文全链路强制传播：REST、MQTT、Redis Streams、定时任务、缓存和时序查询均不可缺失 tenant id。
- PostgreSQL 行级安全或等价的数据库强制隔离；补齐组合唯一键、外键、租户级索引和跨租户自动化攻击测试。
- RBAC 2.0：平台、租户、项目/空间三级角色，自定义角色与权限集合；用户邀请、禁用、会话吊销、密码策略和 MFA 预留。
- 租户配额：设备数、用户数、消息速率、存储保留期、API 频率；超限行为明确且可审计。
- 全量审计日志、操作人/代入人追踪、导出与保留策略。
- 把演示数据从生产初始化链路剥离，建立 production / demo 两套明确启动模式。

完成门槛：自动化证明任何 API、消息、缓存和查询均无法跨租户访问；配额和审计覆盖全部写操作；生产模式启动后没有演示租户或设备。

### V0.4：设备生命周期与控制

- 设备批量注册、导入、分组、标签、凭据轮换/吊销、证书认证和设备模板。
- 客户端属性、服务端属性、共享属性与设备影子，带版本号和冲突策略。
- 双向 RPC：请求、设备回执、超时、重试、取消和完整状态查询。
- 网关与子设备模型，支持网关代认证、代上报和子设备上下线。
- OTA 任务基础：包管理、灰度批次、进度、失败回滚与审计。

完成门槛：设备从入网、运行、控制、轮换凭据到退役的全过程可管理和追溯。

### V0.5：规则引擎与告警中心

- 计算字段、事件模型和规则 DSL；后续演进为可视化 DAG，不直接开放任意脚本执行。
- 规则节点支持过滤、转换、聚合、阈值、持续时间、离线、去抖、关联和定时触发。
- 告警产生、升级、确认、指派、恢复、关闭和评论时间线。
- Webhook、邮件及可插拔通知通道；重试、签名、限流、熔断和死信可观测。
- 规则版本、草稿/发布、回滚、模拟执行和测试样本。

完成门槛：租户无需发版即可配置常见规则；规则失败不阻塞主数据链路，且可以定位、重放和审计。

### V0.6：资产、仪表盘与运营工作台

- 资产树、关系图、客户/项目/站点模型，支持设备与资产多维关联。
- 仪表盘、组件库、变量、时间范围、权限、模板、分享和大屏模式。
- 告警工作台、设备运营视图、批量操作、报表计划与 CSV/Excel 导出。
- 移动端自适应和面向最终客户的只读门户。

完成门槛：租户可独立完成“建资产—接设备—配规则—做看板—处理告警”的完整业务闭环。

### V0.7：开放平台与集成生态

- 版本化 OpenAPI、AccessKey/OAuth2、作用域、签名、限流、幂等键和调用审计。
- Webhook、MQTT/Kafka 数据转发、数据库/对象存储落地和常见云服务连接器。
- 协议适配器与规则节点 SDK，提供兼容性测试套件和示例工程。
- 租户配置、物模型、规则、仪表盘和资产的导入导出与环境迁移。

完成门槛：第三方系统可以只通过公开接口完成租户内主要操作，新连接器不修改核心服务。

### V0.8：云原生、高可用与安全合规

- Kubernetes/Helm 部署、无状态服务水平扩展、滚动升级、优雅停机和自动伸缩。
- 评估并落地可水平扩展的消息与时序存储方案；去除单活 Transport 的吞吐上限。
- PostgreSQL、缓存、消息和时序数据的备份恢复、RPO/RTO、跨可用区部署和灾备演练。
- OpenTelemetry、指标/日志/追踪、租户级用量观测、SLO 和告警值班体系。
- 威胁建模、依赖与镜像扫描、密钥托管、TLS/mTLS、数据加密、渗透测试和隐私合规基线。

完成门槛：在参考集群上完成滚动升级、节点故障、存储恢复和 30 天稳定性测试，达到公开的 SLO。

### V0.9：商业化 SaaS

- 自助注册、租户开通、试用、套餐、功能权益和租户生命周期。
- 用量采集与对账：设备、消息、存储、规则执行、API 和通知；数据可追溯、可重算。
- 订阅、账单、优惠、欠费策略和支付渠道适配层；不在核心域硬编码单一支付厂商。
- 平台运营后台、客户支持代入审批、公告、工单集成、租户迁移和数据删除流程。
- 白标基础：品牌、域名、邮件模板和登录页配置。

完成门槛：新客户可以自助完成注册、试用、升级、用量查看和续费，平台方可以运营并审计全过程。

### V1.0：SaaS GA

- 冻结兼容性策略、API 生命周期、数据库升级/回滚和支持周期。
- 建立明确的参考容量档位；初始 GA 目标为单集群 100 个活跃租户、10 万注册设备、2 万并发连接、持续 5,000 条消息/秒，最终数值以容量模型和压测报告为准。
- 核心链路可用性目标不低于 99.9%；租户越权事故为零；关键恢复演练满足既定 RPO/RTO。
- 发布运维手册、管理员手册、设备接入 SDK、迁移指南、安全白皮书和服务状态页。

完成门槛：设计伙伴在真实业务中连续运行至少 30 天，通过安全、容量、计费准确性和灾备验收后再开放正式商用。

## 5. V1.x 与 V2 方向

- V1.1：HTTP、CoAP、LwM2M、Modbus TCP/RTU、OPC UA 等协议与边缘网关。
- V1.2：规模提升到多集群和十万级并发连接，支持数据分层、冷热存储和区域部署。
- V1.3：企业能力，包括 SSO/SAML/OIDC、SCIM、审批流、专属实例和更细粒度数据权限。
- V2.0：多区域 SaaS、边云协同、应用市场、白标与合作伙伴体系。
- V2.1：受控 AI 能力，包括自然语言查询、异常检测、物模型草稿和告警归因；AI 不能绕过租户权限和审计。

## 6. 最近三个实施里程碑

1. V0.3-A 生产初始化与租户隔离：移出演示种子、数据库强隔离、跨租户安全测试。
2. V0.3-B IAM、审计与配额：自定义角色、邀请/会话治理、全量审计和资源限额。
3. V0.4-A 设备生命周期：批量注册、凭据轮换、属性/影子和 RPC 最小闭环。

每个里程碑启动前单独编写 spec，并明确数据迁移、回滚、容量、安全和验收方案。
